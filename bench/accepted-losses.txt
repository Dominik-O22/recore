# Every loss of a corpus total that a change was let to land with, one a line, with its reason:
#   Worse: <corpus>/<run> <count> <base> -> <head> (<difference>) <reason>
# `./check.sh --against <base>` prints the line of each total that got worse. A change accepts a
# loss by adding that line here with the reason after it, and the reviewer reads the lines its
# diff adds. A line accepts a loss of its run and count as large as it names or smaller, so it
# may name more than the run lost: its difference has to be what its two totals give. Only the
# lines a change adds count, and a change that adds one lands alone. No line accepts a binary
# that lost its analysis or a decompiler that fails on more functions.
# This file is a record and only grows: a change that takes out or edits a line here fails its
# run. Comments may change.
Worse: corpus-kmod/signatures returns a value or not right 2101 -> 2087 (-14) Kernel prototypes for a module's imports (#208). A function that ends in a call to an import now known to return a value, such as `queue_work_on`, reads as returning it. 62 functions that do return it are newly right and 76 that return nothing newly wrong. A tail call to the import is mostly the same code in both. In a few, such as `asus_rfkill_notify`, another path leaves the result register unset, which says the function returns nothing. #220 is about reading that and the callers.
Worse: corpus-kmod-android/signatures returns a value or not right 2196 -> 2187 (-9) The same knock-on of #208: 13 functions newly right, 22 newly wrong.
Worse: corpus-kmod/signatures parameters wrongly called a pointer 0 -> 4 (+4) Kernel prototypes (#208). The `unsigned long arg` of `ftdi_ioctl`, `joydev_ioctl`, `joydev_compat_ioctl` and `lo_ioctl` goes to `copy_from_user` or `copy_to_user` as a user pointer for some commands and is a number for others. DWARF calls it a number, so this disagrees with the truth and is not an error.
